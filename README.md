# 视窗 · Tapa（零猜测八邻环推理）

> *一个格子上的三个数字说的不是"周围有几格黑"，而是"周围的八格里黑段怎么分组、从正北顺时针数过去哪段在前"。
> 出货的每一局都先用玩家也会用的那五条规则推到底过一次，唯一解再由第二套互不信任的穷举代码逐格复核。*

浏览器原生的 **Tapa / 视窗**：无构建步骤、无打包器、**零美术与音频文件**——棋盘、数字、方位锚点、
虚线环、命中判定全部由 `<canvas>` 现画，音效由 WebAudio 合成（`js/audio/synth.js`），运行时依赖 **0 个**。

本作占的是 Nikoli 的 *Tapa*：一格的线索是**环上黑格的分段长度**，另有两条全盘约束
（白格连成一整片、任何 2×2 不许全黑）替它管住剩下的格子。

---

## 规则（原文）

- 盘面是方格纸，每一格最终染成**黑**或**白**。
- **带数字的那一格自己就是黑格**。它周围的八格连成一个环，数字按**顺时针、从正北起**读：
  先数北边那一段有多长，再数下一段（`RING_ORDER`，`js/engine/tapa.js:27-36`；渲染层的方位锚点读同一张表，
  `js/render/board.js:21-30`）。
- **环在盘心是圈，在边上不是**。盘心八格里北与西北相邻，所以两端都黑时那是**一段两格**；
  边上/角上的环被棋盘外断开，是一条**路径**，首尾不接头（`ringRuns`，`js/engine/tapa.js:138-155`；
  断言 `角上两端黑读作 1 1（缺口在棋盘外，不接上）`、`北与西北相邻，读作一段 2`，`tools/engine-test.mjs:150,154`）。
- **顺序是线索的一部分**：`2 1` 与 `1 2` 是两条不同的线索，比较时逐位比，不做旋转归一
  （`sameRuns`，`js/engine/tapa.js:163-167`；断言 `顺序反过来就不是同一条线索`，`tools/engine-test.mjs:180`）。
- **`0 0 0` 是一句实打实的证词**，不是"这里没数字"：它说这一格是**白格**且它八邻全白。
  "没数字"用的是另一个值 `-1`（`js/engine/tapa.js:18-23`，`isZeroClue`，`js/engine/tapa.js:70`）。
- 一条线索最多三个数字：**环上出现四段黑**的那种格子在题面上**不带数字**（`clueFrom` 在 `runs.length > 3` 时
  返回 null，`js/engine/tapa.js:287`；`cluesFrom`，`js/engine/tapa.js:297-307`）。
- **任何 2×2 不许四格全黑**（`no2x2Pass`，`js/engine/tapa.js:446-477`）。
- **所有白格必须 4-连通成一整片**（`whiteComponents` + `linkPass`，`js/engine/tapa.js:485-617`）。

内部格只有 2⁸ = 256 种染法，所以"这些数字允许环上长成什么样"是一个**能枚举、能取交**的有限集，
不需要猜（`ringPatterns`，`js/engine/tapa.js:183-202`）。这就是本作全部的推理地基——也是
`js/engine/tapa.js:10` 那句"搜索只活在 `count.js` 里"能成立的原因。

## 怎么玩

浏览器里：点格子染色，拖动连续染，卡住了按提示。

| 操作 | 行为 |
|---|---|
| **点一格** | 按 未知→黑→白→未知 轮转（`nextValue`，`js/engine/tapa.js:941-944`；一次点击一步历史，`js/engine/tapa.js:933-939`）。实测：`ink` 场景「点一格落黑」「再点同格变白」「第三点回到未知」 |
| **拖动** | 用**当前画笔**连续染色，**一整笔算一步**（`setAll`，`js/engine/tapa.js:947-960`）。实测：「一笔只算一步」「一次撤销退掉整笔」「来回拖仍然只算一步」 |
| **右键拖** | 就是橡皮：把扫过的格擦回未定（`js/main.js:413-415`）。实测：「右键拖过就把墨擦回未知」 |
| **点带数字的格** | 允许，而且**罚**：那一格必须是黑格，第一点恰好对、第二点变白就当场被点名（`js/engine/tapa.js:341-367`）。实测：「点线索格落黑（与规则一致）」「再点变白就是错」「错一步就被点名一次」 |
| **`B` `W` `E`** / 三个画笔按钮 | 换画笔为黑 / 白 / 未定（`js/main.js:509-518`）。实测：「e 键换画笔」三条 |
| **`H`** / 「提示」 | 说出**当前推得出的那一格**、用了哪条规则，并**替你落子**，按一次求助计一次。**你的墨与线索冲突时不落子、不计次**（`js/ui/game.js:130-165` + `js/main.js:251-256`）。实测：「矛盾时不收钱」「这时提示才肯落子」「这次才计一次提示」 |
| **`Z`** / 「撤销」 | 退掉上一步（点、拖、提示各算一步，历史上限 600 步 `js/engine/tapa.js:920-924`）。**退掉提示落的格不退还提示次数**（`js/ui/game.js:115-125`）。实测：「撤销不退提示次数」「续局不能撤销到重开之前」 |
| **`P`** / 空格 / 「暂停」 | **同时**停表和冻盘（`js/main.js:683-753`）：冻住期间左点、右擦、拖、撤销、提示、换画笔**一律不落地**，盘上一个字都不改、表针也不加，被挡下的那一刀在 `#state-line` 上写明"什么没有落地"（不是把控件弄灰）。**拖到一半**时按暂停，抬手那一笔整个作废（`js/main.js:438-441`）。读盘面的操作不挡：暂停里仍然量得到几何、读得到状态。实测：`pause` 场景 17 把挡刀各自点名、`挡刀总数等于名册长度`、`冻住的 2.1 秒里表针没加`、`画面一个像素都没改` |
| **`1`–`5`** | 只在**选档页**换档；棋局页里数字键不换局（`js/main.js:517`）。它起的是**新的一局**，所以不带挡刀的那把闸：`begin()` 自己解冻、自己把表归零（`js/main.js:287`），记的是这块新盘真实花掉的时间。实测：「新局之前确实冻着」「换一局接手新盘就解冻」「换一局把按钮画对」「新局不带着上一局的表」 |
| 「换一局」「回选档」「清空存档」 | 同档换种子 / 回选档并留下可继续的一局 / 内存与磁盘两边都清（`js/store.js:215-222`） |

内容有三层，**五档全部现场可出**：**章节题单**（五档 × 6 局 = 30 局，构建期烘好、逐字节复验，
`js/data/library.js`）、**现抽一局**（`generate()` 就在浏览器里跑；`SAMPLES=24 npm run balance` 实测
每局出题耗时 入门 1.1 / 简单 1.3 / 中等 7.1 / 困难 20.5 / 大师 55.3 ms）、
**当日一局**（种子只由本地日期决定，`dayKey`，`js/engine/rng.js:36-42`；题单走完之后才按
`day|<日期>|<档位>|<序号>` 出，`js/main.js:82-90`）。种子表意即用：`Math.random()` 不在出题路径上，
存档里也只有一个种子而没有盘（`js/main.js:76-81` 注释 + `js/store.js:174-191`）。

```bash
npm start            # 零依赖静态服务 → http://127.0.0.1:5312
npm run dev          # 同一个端口 5312（验证台用的也是它）
npm run electron     # 桌面壳（electron/main.cjs，同一份代码，无构建）
```

## 这个仓敢承诺什么

每条后面括号里就是它的实测出处；写不出出处的话就不写在下面。

1. **零猜测**：出货的每一局都能**只用那五条规则从空盘推到底**，一次都不回溯——`solve()` 就是接受测试，
   推不完就整盘丢掉（`js/engine/generate.js:196-200`）。实测：30 局题单在浏览器里 **30/30 推得完**
   （`tools/scenarios.js:503`「三十局全部推得完（零猜测）」）；`SAMPLES=24 npm run balance` 另打
   **15/15 张新盘从空盘推到满盘，全程不回溯**，而且这一条把"步数 == 格数"一起钉住
   （`tools/balance.mjs:122`）——每格恰好写一次，所以推导步数恒等于盘面格数（实测 25/36/49/81/121）。
2. **唯一解由第二套互不信任的实现逐格复核**：`js/engine/count.js` **一行 import 都没有**，
   自己重写邻居表（`count.js:44-60`）、自己的段读法（`count.js:71-86`）、自己的逐位比较（`count.js:93-97`），
   只按行主序穷举（`count.js:300-325`）。预算 **500,000 节点**，`node tools/bake.mjs --check` 实测
   **五档各自「超预算 0」**、**30/30 局在预算内被穷举证完唯一解**（最深 79,444 节点，出现在 11×11 大师档）。
   "没数完"绝不读成"唯一"：`exhaustive` 是显式状态（`count.js:178-183`），预算截断时 `forced` 一格都不给
   （`count.js:333-341`），`bake` 直接拒收该种子（`tools/bake.mjs:161-164`），`balance` 把超预算**记为不成立**
   而不是跳过（`tools/balance.mjs:156-169`）。还有**第三条意见**：`tools/engine-test.mjs` §7b 把 `count.js`
   的解数与 `2^16` 全枚举逐盘对数，**12 盘全对、12 盘都走穷**，且对照组里唯一/多解/无解三种都真的出现过。
3. **提示是推得出的下一步，而且说完就真落子**：提示读的是**线索自己产出的推导脚本**
   （`this.script = solve(this.board).rows`，`js/ui/game.js:45`），不看玩家的墨——
   所以错的落子骗不出"提示也认同"。`hint` 场景在**困难档**一整局上逐条断言：一路提示能走完这局、
   **提示次数 == 格数（81）**、说的规则都在规则表里、不越界、"说完就真落子"、面板文本与引擎那条逐条一致
   （`tools/scenarios.js:829-837`），并且**两种点格说法都真的出现过**（见下条与"不承诺"第 3 条）。
4. **提示在你的墨与线索矛盾时不收费**：`conflict` 场景先落一格与线索相反的墨，要求提示 `conflict`、
   `#stat-hints` 仍是 0、说明点名那一格并说清该落哪一色，**擦干净之后提示才恢复计费**；
   画布上还要求那一点被 `error` 色圈出（`onPulseRect(...) >= 8`）。
5. **判胜走独立验收**：`verify()` 直接按游戏规则重读盘面（`js/engine/tapa.js:802-837`），
   `complete()` = 满盘 + `verify()` 返回空（`js/engine/tapa.js:856-859`），**不读推导脚本**——
   提示逻辑写错伪造不出一场胜利。实测：`ink` 场景「满盘皆黑不算通关」「满盘皆黑被大量点名」，
   `conflict` 场景「照解画完就赢了」+「差一格就通不过独立验收」+「穷举的解与玩家画完的解逐格同盘」。
6. **`0 0 0` 与"这里没数字"在画面、引擎、题面三处都不混**：`NO_CLUE = -1`（`js/engine/tapa.js:23`），
   三个零是**青色**外加一圈**虚线环**，普通线索是琥珀色、无格什么都不画
   （`js/theme.js:42`、`js/render/board.js:208-220`）。实测：`zero` 场景 28 条断言——虚线环只在 `0 0 0` 那一格
   出现（两处对照组各要求采到 0 个点）、青色零与琥珀零互不出现、`0 0 0` 那一格自己是白格而带数字的格是黑格。
7. **难度是量出来的**：五档的 `band` 是**选取目标**，`npm run balance` 是门禁。
   `SAMPLES=24 npm run balance` 实测中位分数 **41.8 < 63.2 < 88.3 < 154.7 < 233.2**（严格递增），
   五档**出题 24/24、拒收 0、命中 band 100%**，`结论：阶梯与两条承诺都成立（exit 0）`。
8. **暂停冻住的是两样东西：表针和盘面**。同档纪录先比提示次数、再比步数、最后才比 `ms`
   （`js/store.js:157-164`），而 `#stat-time` 与落进存档的那个数读的是同一个 `clock()`——
   所以"只停表、不停盘"的暂停等于发一段免费思考时间，榜上那个数就不再是玩家花掉的时间。
   闸装在**写手**身上而不是输入设备上：五个写手（换画笔 `js/main.js:168`、提示 `:249`、撤销 `:265`、
   起笔 `:410`、收笔 `:438`）加台面三条直接改盘的路（`:545`、`:552`、`:562`）各自先退回再动手，
   键盘那一路（H/Z/B/W/E）走的就是这几个函数所以**继承**同一把闸，而**拖到一半**按暂停的那一笔
   整个作废（预览擦回去、不提交）。解冻只有两处（`setPaused(false)` 与接手新盘的 `adoptFreshBoard()`，
   `js/main.js:711-733`），两处都把按钮画对，所以不存在"按钮写着继续、点了却什么也不动"的死锁。
   挡下来的每一刀写进 `#state-line` 点名，**不是把控件弄灰**。实测：`pause` 场景 **134 条断言**——
   17 把挡刀逐一点自己的名、`挡刀总数等于名册长度`、冻住的 2.1 秒里 `elapsed()` 恰好加 0 且
   五条读数与画布像素全不动、赢局落进存档的 `ms` 不含这段冻结、暂停中回选档时存档写的就是冻住的那个数。

## 这个仓**不承诺**什么

这一段是上面那八句的可信度来源——反面写清楚，正面才算数。

- **不承诺"状态行会告诉你有几处对不上"**。`js/main.js:128-132` 有两支文案，第二支
  `${problems} 处对不上` 在真实行为里**到不了**：我这轮把五档出货盘各取一局（`newbie-01`…`master-01`）
  的**全部单格与双格染色**扫完 **51,048 个状态**，再加 4,000 个随机半盘填充，共 **55,048 个**，
  满足 `problems > 0 && !stuck` 的是 **0 个**。原因是 `reachable()` 的廉价扫与 `verify()` 读的是同一批规则，
  凡 `verify()` 看得见破法的盘面，廉价扫已经先判了无解（`js/ui/game.js:56-63` 把两者放在一起）。
  → 破法**条数**只走 `#stat-conflicts`（`js/main.js:123`），守它的是
  `tools/scenarios.js:933`「状态行不报处数（处数那一支在真实行为里到不了）」。
- **不承诺"每个可点的东西都不小于 44 px"**。44 的下限有两处：组件自己那句
  （`css/game.css:61-70` 的 `min-height: var(--touch-min)`），以及手机轮补的硬下限
  （`css/game.css:443-455`，`min-height/min-width: 44px !important`，覆盖 `button:not(.link)`
  / `select` / `input` / `textarea` / `a[href]` / `[role="button"]`）。带 !important 的那条会
  无条件盖掉组件规则，所以**豁免必须在它自己的选择器里写出来**，而不是只靠组件那句 `min-height: 0`。
  全仓**只有一条明写的豁免**：`button.link`（`css/game.css:93-100`，`min-height: 0` + 12px 字），
  只有页脚「清空存档」一个控件戴这个 class，`tools/scenarios.js:1499`「全屏只有清空存档豁免 44」
  与 `:1495`「豁免的那条链接确实小过 44（豁免不是空集）」钉的就是这一件事——
  后者是反空转：把豁免改成摆设（选择器不再跳过它）时，红的是这一条而不是那条名册。
  量法也照实写：`layout` 场景对 `#app button` 里**有 client rects** 的逐个 `getBoundingClientRect`、
  两轴都取整比较，并把名册按 id 钉死（`tools/scenarios.js:1473-1492`；棋局屏 11 条、选档屏 10 条，
  两屏的名册里都有 `btn-pause`——暂停按钮在共用的页眉上）。
  **画布里的格子不是 DOM 控件**，走的是另一套下限：边长 `Cell.min 26 … Cell.max 64`
  （`js/theme.js:79`），`layout` 断的是这个区间；900×900 验证窗口下 11×11 实测每格 44 px，
  那是**读数不是承诺**——窗口更小时它就是 26。
- **不承诺"提示永远告诉你第几行第几列"**。环规则在"只剩最后一种摆法"那一支用的是**方位说法**
  （「北方向那一格」，`js/engine/tapa.js:435-437`），不是行名列；其余四条规则用的是行名列。
  两种说法都被要求**真的命中它刚落的那一格**——`tools/scenarios.js:835`
  「两种点格说法都真的出现过（不是只测到一种）」，本轮实测 行名列 / 方位说法两种各出现过
  （`hint` 场景打的是 `行名列 N 条 · 方位说法 M 条`）。
- **不承诺"线索集已是最简"，也不承诺"每条线索都是承重墙"**。剪枝是**三轮贪心删除**
  （`pruneClues`，`js/engine/generate.js:122-141`），而**没有任何一条断言**去测"留下的某一条还能不能再删"。
  实测只到两件事：`gen` 场景的「${档位} 数字确实被删过」（题面数字少于格数，
  `tools/scenarios.js:373`）和 `balance` 打出的线索数量级（本轮实测中位：入门 6/25、简单 9/36、
  中等 11/49、困难 17/81、大师 26/121）。谁哪天要把"线索最少"写成承诺，就得先加一条逐条重删的测量。
- **不承诺"任何一块 Tapa 盘面都能被这五条规则推完"**：这五条**不完备**（这是取舍不是缺陷）。
  推不完的盘不出货，所以本作能出货的难度上限就是这五条的极限。反证（权重 3）是最后一条，
  入门/简单两档在 `TIERS` 里就写着 `useNishio: false`（`js/engine/generate.js:160-161`）——
  那两档的"推得完"是**更硬**的要求，实测反证步数中位 入门 0 / 简单 0 / 中等 0 / 困难 6 / 大师 8。
- **不承诺 30 局之外的题单**。章节是烘好的固定 30 局，`bake --check` 逐字节复验；超出题单就是现抽。
- **不承诺二乘二禁在每一档都出场**。`balance` 的规则出场表只要求每档"线索自黑 + 环上相容 +
  （二乘二禁 **或** 白格连通）在场"（`tools/balance.mjs:265-268`），本轮实测中等档代表盘
  二乘二禁 0 次、白格连通 9 次。
- **未验证**（跑过才有资格写，这里没跑过）：Safari / Firefox / 移动端实机——门禁只在本机 headless Chrome

## 难度是量出来的

`TIERS[]` 里读得到的四个旋钮（`js/engine/generate.js:159-165`），分数带是**先跑分位表再填进来的**：

| 档 | 盘面 | 黑格密度 | 允许反证 | 必带 `0 0 0` | 选取目标 band（代码常数） | 题本 | 本轮实测中位（SAMPLES=24） |
|---|---|---|---|---|---|---|---|
| 入门 | 5×5 | 0.30 | 否 | 是 | 30–48 | 6 局（烘好） | 41.8 |
| 简单 | 6×6 | 0.33 | 否 | 是 | 48–72 | 6 局（烘好） | 63.2 |
| 中等 | 7×7 | 0.36 | 是 | 是 | 76–118 | 6 局（烘好） | 88.3 |
| 困难 | 9×9 | 0.38 | 是 | 是 | 126–196 | 6 局（烘好） | 154.7 |
| 大师 | 11×11 | 0.40 | 是 | 是 | 200–274 | 6 局（烘好） | 233.2 |

分数是**推导事件按规则加权后的和**，再加"每一次环上写入挤掉了多少可能性"的份额
（`score += row.rule.weight + ELIM_WEIGHT * row.elim`，`ELIM_WEIGHT = 1.5`，
`js/engine/tapa.js:310-324` + `js/engine/tapa.js:744-753`）。所以它同时反映盘有多大、
要夹几层、以及每一格玩家要想多久。**新增一条规则就会挪动这些带**——这是 `balance` 存在的理由。

别把两套中位数搞混：上表是**命令行** `SAMPLES=24 npm run balance` 的 24 抽样中位；
浏览器 `gen` 场景打的是另一套东西（每档 4 个固定种子、取排序后第 2 个），本轮实测
`[36.3, 57.4, 86.3, 143.8, 228.6]`——两个都是真数，口径不同，不可互换（详见 `DESIGN.md` §9）。

| 规则 | 说什么 | 权重 | 实测出场（每档一张代表盘，`rules|<档>` 种子） |
|---|---|---|---|
| 线索自黑 | 带数字的格自己就得染黑；`0 0 0` 的格自己得染白 | 1 | 6 / 8 / 9 / 17 / 27 |
| 环上相容 | 把这条环上活下来的摆法列出来取交，所有人都同意的就写下 | 1 | 17 / 24 / 23 / 50 / 85 |
| 二乘二禁 | 2×2 里已有三格黑 ⇒ 第四格必白 | 1.6 | 0 / 0 / 0 / 1 / 2 |
| 白格连通 | 被黑格围死的一片必黑；一染黑就把白格切两半的那格必白 | 2.2 | 2 / 4 / 9 / 13 / 3 |
| 反证排除 | 假设这格是黑（或白）就撞墙 ⇒ 它只能是另一色 | 3 | 0 / 0 / 8 / 0 / 4 |

（五列依次是 入门 / 简单 / 中等 / 困难 / 大师。每条恰好写满一格，所以五行相加就是 25/36/49/81/121。）

五条都不含猜测：**每一条写下的格子，对盘面的每一个解都成立**（论证见 `DESIGN.md` §4、§7），
所以"铅笔推得完 ⟹ 解唯一"。反方向不成立——有些唯一解的盘这五条推不完，那正是生成器要丢掉的东西
（`tools/engine-test.mjs` 的「推不完就是不出货」与 `gen` 场景的「非唯一盘不会被规则误判推完」两头都钉着）。

## 上线的到底是哪一批文件

这个仓没有打包器：站点=一次文件拷贝。以前「拷哪些」写在 `pages.yml` 的 `run:` 里（手抄的几行
`cp`）。本地 `index.html` 直读仓库根，永远自洽；线上却按那份清单拷，于是页面后来引用的
`manifest.webmanifest`、`sw.js`、`icons/*` 可能一个都没上去——线上 404，而仓里的引擎测试与
真浏览器闸全绿，因为它们跑的都是仓库根，没有任何一步在「按清单拷」的那个环境下加载过页面。

现在清单只有一份，住在 `tools/assemble-site.sh`：CI 调它拷 `_site`，本地闸调它拷临时目录，
然后**对拷出来的产物**提要求（`tools/deploy-set.mjs`）：

- **W 清单与页面同源**：`pages.yml` 里必须真有 `run: bash tools/assemble-site.sh <dir>` 这一行，
  `ci.yml` 里必须真有 `run: node tools/deploy-set.mjs`。认的是调用那一行，不是文件里出现过这个
  路径——注释里本来就会写它，只 grep 字符串会被一句散文喂绿。
- **R 引用可达**：引用不靠手打名单。从 `index.html` 的 `href/src` 出发，凡解析出来是 `.js`/`.css`
  的就把那一站也扫一遍（CSS 的 `url()`、JS 去掉注释后的 `'./…'` 字面量、`new URL(x, base)` 的两种
  基、`navigator.serviceWorker.register`、`scope`），`manifest` 的 icons/screenshots/shortcuts 各自
  的 `src` 也算引用。取径上读不到的那一站本身就是红（读不到＝这一站根本没扫）。每条引用都必须在
  产物里且非 0 字节；绝对路径单列一条红，因为 Pages 挂在 `/<repo>/` 前缀下会跳出去。
- **P 位图不许说谎**：`manifest` 声明的 `sizes` 必须等于 PNG IHDR 的真实宽高——文件图标读文件头，
  内联成 base64 的图标先解码再读同一段。后一条不是可选项：图标可能住在清单里而不是盘上的 `.png`
  （有的仓另有一条"零二进制文件"的承诺，那条只约束"有没有 .png 这个文件"）；如果 P 段只筛文件名，
  声明写 512 而真图 192 就一路放行。
- **钉住两个数**：R 段实际检查的路径条数（`29`）与这一次跑的断言条数（`47`），两个数
  都钉在 `tools/deploy-set.mjs` 顶部的那对常量里。没改页面却掉了，说明解析断了；删掉一张图标会同时
  少一条 R10 与那张的 P1/P2，所以两个数一起钉，断言条数能漂就是闸在缩水的信号。这一节故意只写数值、
  不写那对常量的名字，也不写别仓文档闸的编号：有的仓的文档闸会拿"文档里出现过的同名标识号"回数它
  自己的条数，还有的会把文档里点到的每个组编号逐个核对"这一轮真的发过"——两道闸共用一个名字，
  或者在本仓的文档里出现一个本仓没有的组编号，打红的都是不相干的那一边。

`tools/deploy-set-selftest.mjs` 是这两颗钉的阳性证明：它把仓库复制到临时目录，照着每一类断言
各下一刀（X1 清单不收位图目录 / X2 模块边改名 / X3 CSS 写绝对路径 / X4 `start_url` 绝对 /
X5 删光 >=512 图标 / X6 少一个必填字段 / X7 声明尺寸与真图不符 / X8 workflow 不调脚本 /
X9 CI 不跑闸 / X10 是阴性对照——往入口 JS 追加一行只写在注释里的假路径，闸必须仍然绿、条数仍然
`29`、断言仍然 `47`；X11 og:image 退回相对路径 / X12 og:image 的前缀指向别的 slug /
X13 内联位图谎报尺寸——只在有靶子时下：X11/X12 要页面上那句 og:image，X13 要清单里真有一段 base64
图标，没有就打印 SKIP；反过来 X1 没有位图目录可砍时改砍 css，P 段一位都不核时台架直接报靶子不够），
要求每一刀都让闸**点名**变红。靶子从 `DEPLOY_SET_DUMP=1`
的出处表现挑（取径真的会读的那支 JS / 那一张 CSS，不写死某一个仓的入口名），所以页面改了、仓与仓
不同，台架跟着走。

`node tools/deploy-set.mjs` 与 `node tools/deploy-set-selftest.mjs` 就是 CI 跑的那两条命令本身
（package.json 里的 `deploy-set` / `deploy-set:selftest` 只是同一支脚本的 npm 入口）；本仓的整闸在 `tools/verify.sh` 的 `=== deploy-set ===` 那一段也各跑一次。它们红的时候并进本仓那条出口的退出码——这一条是这么证的：
把 ci.yml 里那行 `run: node tools/deploy-set.mjs` 砍掉，本仓整闸必须点名红且退出码非 0。
所以「本地全绿、线上 404 自己的 manifest / sw.js / 图标」这一类坏法在本地就会红。
